# 3D stages 4–5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 3D snapshots in the dossier (stage 5) and concept renders from the 3D camera (stage 4).
**Architecture:** Dossier request carries up to 4 JPEG/PNG data URLs, validated and re-encoded server-side, embedded in the immutable HTML. Render `view.camera {x, y, yaw}` (mm, degrees) drives a world-space pinhole camera path in the concept renderer.
**Tech Stack:** FastAPI, Pillow, Jinja; three.js view (stage 1).
**Spec:** `docs/superpowers/specs/2026-11-26-3d-design.md`

## Global Constraints
- No migration. Dossier views: max 4, each ≤ 3,000,000 chars, PNG/JPEG only, decoded by Pillow, pixel guard, re-encoded JPEG ≤ 1200 px.
- `view.camera` requires `view.room_id`; camera clamped into the room's bounding box (inset 150 mm). yaw −360..360.
- ComfyUI ignores the camera (text-to-image).

## Review Focus
- Camera inside furniture / facing a wall / in a corner → no crash, image produced (concept test).
- Polygons behind the camera are clipped, not mirrored (test: furniture behind camera leaves the image unchanged).
- Data URL with wrong prefix, bad base64, a GIF, a decompression bomb → 422 (dossier tests).
- Unsaved plan when pressing "Render this view" → user told to save first; nothing charged.
- No WebGL when generating a dossier → dossier still generated without views, user told.
